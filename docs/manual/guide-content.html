1 / IRAF — fast reduction

Use for an optical classification quick look. The pipeline uses archived calibration and does not perform the full bias/flat, fringing or telluric corrections.

  1. Prepare a working copy and check startup.

    Activate pessto, then use the preparation helper to copy inputs into a fresh run. Keep the raw basename. Check the shell commands:

    PESSTOFASTSPEC -h
PESSTOFASTSPEC --version

    Resolve startup or graphics failures using troubleshooting before reducing.

  2. Start interactive extraction.
    PESSTOFASTSPEC RAW_EXPOSURE.fits -i

    Record the selected archive arc and sensitivity curve. To choose them explicitly, use matching files:

    PESSTOFASTSPEC RAW_EXPOSURE.fits -i -a MATCHING_ARC.fits -s MATCHING_SENS.fits

    Add -d if you need to choose a better dispersion slice for aperture identification. -t requests tracing with another frame; select a suitable reference when prompted.

  3. Inspect the wavelength / sky comparison.

    Compare the observed, reference and shifted sky lines. Check that a proposed shift aligns multiple usable features. Read the terminal prompts; the fast route may apply the correction automatically. Record weak or unavailable sky validation rather than treating it as a pass.

  4. Find the target and set the aperture in apall.

    Answer yes to Find/Recenter/Edit apertures when offered. Check the source against acquisition/finder evidence. Delete an incorrect aperture, mark the correct trace and set its limits. Do not select a host or nearby star merely because it is brighter.

    KeyIn the aperture editor
    ?Show the active task's help.
    d, mDelete the aperture near the cursor; mark and centre a new one on the intended peak.
    l, uSet the lower/upper aperture edge at the cursor.
    bEnter background fitting for the selected aperture.
    rRedraw.
    w then x/yEnter window mode and zoom the corresponding axis; follow its cursor prompts.
    w then aRestore the full window. A bare a in the aperture editor instead toggles ALL apertures.
    qFinish aperture editing and return to the next pipeline prompt.
  5. Set background regions, then inspect the trace.

    Inside background mode, use z to remove an unsuitable sample region and s at each endpoint to define a region. Choose clean background on both sides of the source, avoiding other traces and bad pixels. Press f to refit, inspect the fit, then q to return to aperture editing. Press q again when the aperture is ready. The same key can mean different things in different editors; ? shows the active help.

    Answer yes to Trace/Fit trace interactively. In the trace-fit window: d excludes a bad point, f refits, :order N changes fit order, and q returns. Use the simplest stable fit supported by the data; do not follow cosmic rays or noise at the ends.

  6. Save the aperture, extract and review.

    Answer yes to Write apertures to database, Extract spectra and Review extracted spectra. Inspect the final plot for source signal, sky residuals and suspicious features; use the 2D frame to distinguish cosmic rays from spectral structure. Press q in the IRAF review plot to continue. Preserve database/ with the run.

  7. Keep the outputs and record the limitations.

    *_ex.fits is the extracted spectrum; *_f.fits is the flux-calibrated 1D spectrum; *_2df.fits is the associated calibrated 2D product; *_f.asci is the text spectrum. Retain logs and the selected calibrations. Check the actual product headers before interpretation. Fast reduction is suitable for a reviewed quick look, not automatically a final science product.

Sources: supplied pipeline manual, “FAST EXTRACTION”; PESSTO Handbook pp. 30–33; IRAF aperture-editor help. The IRAF aperture screenshots are retained as historical interface illustrations, not restyled scientific figures. The sky-check screenshot is omitted because its numerical source data are unavailable for faithful replotting.

2 / IRAF — full reduction

The order is raw calibration and 2D wavelength calibration first, then extraction and flux calibration. Work in a new directory and retain all raw data separately.

  1. Activate IRAF.
    conda activate pessto

    Skip if already active. Run the following commands in the terminal; the IRAF path is set automatically.

  2. Prepare a new reduction attempt. 
    python /Users/avinash/Work/Reduction/EFOSpec/scripts/prepare_iraf.py 2024-11-14
    • Input: uncompressed data/2024-11-14/EFOSC*.fits. Use your actual observing date.
    • Output: the next unused runs/2024-11-14/pessto/iraf-full-NN/, containing raw copies and the list helper. Preparation does not start reduction.
    • Next: run the printed cd command.
    • Existing run: skip preparation and list generation; enter that folder and resume.
    Override the input or output folder

    Add --source /absolute/path/to/raw/files for inputs elsewhere, or --runs /absolute/path/to/runs for another output parent. Originals remain unchanged.

    Download list_raw_frames.py separately if needed (requires Astropy).

  3. Generate the frame lists.

    Choose the exact grism/filter/slit values from your headers. This example selects Gr13/Free/slit1.0; defaults are 2×2 binning and fastL/normal readout.

    python list_raw_frames.py --grism 'Gr#13' --filter Free --slit 'slit#1.0'
open inventory.csv
wc -l bias.list arc.list flat.list science.list standard.list

    On Linux or in a terminal, use less -S inventory.csv instead of open; press q to exit. For paired Gr13 standards and their calibrations, use --filter Free GG495. Other options: --binning 2 2 --read-speed fastL --read-mode normal. Use a fresh directory to change selections; existing lists are protected.

    FileContents / review
    bias.listZero-second biases matching detector/readout; ESO may label them DARK. Retain at least three good frames.
    arc.listMatching WAVE lamp spectra. Check timing, line illumination and saturation.
    flat.listMatching spectroscopic FLAT/DOME frames. Check illumination; retain at least three per combination group/OB. Gr16 needs appropriate contemporaneous internal flats for fringing.
    science.listRaw science spectra. Confirm target, night and setup.
    standard.listSTD exposures. Confirm supported spectrophotometric standards; retain the corresponding GG495 standard for Gr13 second-order correction.
    Which FITS headers create the five lists?

    The script reads each primary FITS header using Astropy fits.getheader(). wc -l only counts the resulting filenames.

    ListHeader rule
    bias.listEXPTIME = 0, including biases labelled DARK.
    arc.listESO DPR TECH = SPECTRUM; OBJECT = WAVE.
    flat.listESO DPR TECH = SPECTRUM; OBJECT = FLAT or DOME.
    standard.listSpectroscopic exposure with ESO DPR TYPE = STD.
    science.listSpectroscopic exposure with ESO DPR TYPE = OBJECT.

    Setup selection uses ESO INS GRIS1 NAME, ESO INS FILT1 NAME, ESO INS SLIT1 NAME; detector matching uses ESO DET WIN1 BINX/BINY, ESO DET READ SPEED and ESO DET READ MODE. Biases require detector matching only. Files marked by FILETYPE or PRODCATG are excluded as reduced products; acquisition/non-spectral images are excluded after checking for zero-second biases. The inventory records every file's header values and selection.

    These are candidate selections. Acquisition images, imaging flats and recognizable reduced products are excluded; unknown frame types remain flagged for review in the inventory. Biases match detector settings rather than grism/slit. Do not mix binning/readout modes; this legacy reducer expects 1030×1030 raw frames.

  4. Inspect frames and edit the lists.

    Review the inventory and actual images, then remove unsuitable filenames. Each list must contain one raw basename per line, without headings, comments or blank lines.

    nano bias.list
nano arc.list
nano flat.list
nano science.list
nano standard.list

    In nano: Ctrl+O, Enter saves; Ctrl+X exits; Ctrl+K deletes a line; Ctrl+W searches. Resolve empty lists or missing calibrations before continuing.

    Optional IRAF statistics and image inspection

    Start pyraf in this directory and run:

    images
imutil
imstatistics @bias.list fields="image,mean,stddev,min,max"
imstatistics @flat.list fields="image,mean,stddev,min,max"
imstatistics @arc.list fields="image,mean,stddev,min,max"

    Start DS9, then use display ACTUAL_RAW_FILENAME.fits 1 for each frame, replacing the placeholder with a basename from its list. Statistics alone cannot establish illumination or source identity. Type .exit to return to the shell.

  5. Build and check raw.list. 
    python list_raw_frames.py --combine
cat raw.list

    This validates the five reviewed lists, checks file existence and obvious reduced products, removes duplicate entries, and writes their union to raw.list. If you edit the lists later, retain the old result with --combine --raw-list raw-v2.list and use that new filename for reduction.

  6. Start 2D reduction.
    PESSTOEFOSC2dSPEC -h
PESSTOEFOSC2dSPEC raw.list -i

    The shell wrapper takes raw.list without @. It builds masters from the raw calibration frames included in that list. Do not pass raw bias/flat lists to -B/-F: those options expect prepared master biases and normalized flats.

    Optional calibration overrides

    Use -a arc.list to restrict raw arc selection. Only when reusing reviewed masters for this exact setup:

    PESSTOEFOSC2dSPEC raw.list -i -B masterbias.list -F normalizedflat.list -a arc.list

    These prepared-master lists must already exist. Run this instead of the default command, not after it.

    -C enables the wrapper's cosmic-ray rejection option. Lowercase -b and -f disable bias and flat correction; they are not the full-reduction defaults.

  7. Inspect bias and flat selection.

    At good/bad frame prompts: g accepts a frame, b rejects it, G accepts the remaining frames and s stops selection, as shown by the prompt. Inspect frames before accepting a whole group. Review master bias, flat illumination, saturation and normalized flat. Repeat selection if the master is unsuitable. Confirm each setup before processing it.

  8. Check the arc identification and wavelength fit.

    Choose interactive inspection when asked. Confirm several lines across the usable range; reject blends and incorrect identifications. Review the residual pattern and coverage, not just a small RMS.

    KeyIn identify / wavelength fitting
    ?Show keys for the current window.
    mMark a known arc peak; enter its reference wavelength when prompted.
    lMatch additional lines from the configured line list once a starting solution exists.
    dRemove the selected incorrect feature.
    fEnter/refit the dispersion solution. Inspect residuals there.
    :order NSet fit order in the fitting window; refit with f.
    z, pZoom to an arc feature; restore the original view in identify.
    qLeave the fit window, then leave identify; confirm saving its database record when asked.

    Inspect the propagated 2D wavelength mapping and transformed science frame. A bad solution needs correction before extraction.

  9. Review the science sky-line offset.

    Compare measured and reference sky lines and accept a proposed shift only when supported. Short standard exposures may not support this test; retain the skipped status. The 1D stage may offer a telluric-line check for the standard. Save the applied shifts and calibration associations.

  10. Build the 2D input list and start extraction.

    Write list2D with the wavelength-calibrated science and standard frames produced by this run, one per line. In a clean directory the manual's shortcut is:

    ls t*.fits > list2D
nano list2D
PESSTOEFOSC1dSPEC -h
PESSTOEFOSC1dSPEC list2D -i

    Inspect and edit that list before running: remove old _ex, _f, _2df and other derivative products. Do not trust the wildcard in a reused directory.

  11. Extract each science object and standard.

    Use the same apall aperture/background procedure in the fast manual: identify the source, set l/u, edit background with b, fit the trace and save the database. Review standards as carefully as science targets.

    # Optional: choose the dispersion slice / a reference trace interactively
PESSTOEFOSC1dSPEC list2D -i -d -t
# Replay only an already reviewed, matching extraction database
PESSTOEFOSC1dSPEC list2D -A

    These are alternative rerun commands, not additional mandatory processing passes. Preserve the earlier results before rerunning.

  12. Fit the sensitivity response and inspect corrections.

    Review standard bandpasses, remove contaminated measurements and fit a smooth response. In sensfunc, ? displays help, d deletes the nearest point/star/wavelength according to its follow-up prompt, f refits and q finishes. Check the response over the wavelengths actually supported by the standard.

    The legacy Gr13 workflow can use the blocking-filter standard for second-order correction. Inspect atmospheric/telluric correction and any wavelength check of the standard. Missing calibrators must remain explicit limitations.

    # Optional: explicitly selected sensitivity and atmospheric files
PESSTOEFOSC1dSPEC list2D -i -s sensitivity.list -a atmosphere.list

    -a means arc selection in the 2D command, but atmospheric correction input in the 1D command.

  13. Inspect and save the full reduction.
    • Check 1D/2D products, sky/telluric residuals, calibration edges and flux consistency where setups overlap.
    • Retain standards, response/atmosphere files, arc solutions, database/, logs and tarballs.
    • Confirm target identity and calibration quality; successful execution alone does not establish absolute flux accuracy.

Sources: supplied pipeline manual, “EFOSC SPECTROSCOPY” and “Extraction and calibration”; local PESSTOEFOSC2dSPEC / PESSTOEFOSC1dSPEC scripts; IRAF identify and sensfunc.

3 / EFOSpec — PypeIt reduction

Use one observing date per invocation. The example below is 2024-11-14; replace it everywhere with the required night. The observing night spans noon UTC to noon the next day.

  1. Activate EFOSpec and check the commands.
    conda activate efospec
cd /Users/avinash/Work/Reduction/EFOSpec
efospec night -h
efospec gui -h
    Only if EFOSpec is not installed

    Install in efospec, never in pessto:

    python -m pip install -c constraints.txt -e '.[rapid,plots,desktop]'
  2. Prepare the raw night directory.
    • Copy existing science, standards and matching calibrations into data/2024-11-14/; retain acquisition images.
    • If downloading from ESO, inspect the selection first:
    efospec download 2024-11-14 --with-calibrations --dry-run
efospec download 2024-11-14 --with-calibrations

    Skip downloading if files are already present. Proprietary data require authorized ESO access.

  3. Make the observing log and check the inventory.
    efospec night 2024-11-14 --stage log

    Check target names, times, exposure durations, grism/filter/slit and frame roles. Resolve missing calibrations and wrong-night science frames before reducing. The current default uses native raw calibration and same-night standards matched to the setup.

  4. Run the reduction and report.
    efospec night 2024-11-14 --stage reduce --flux-calibration same-night
efospec night 2024-11-14 --stage report

    Alternatively, run all stages with one command instead of steps 3–4:

    python scripts/reduce_epoch.py 2024-11-14

    To process only a specific target, use its exact FITS OBJECT value:

    efospec night 2024-11-14 --target EXACT_OBJECT --flux-calibration same-night

    Matching standards remain part of the native calibration route. An explicit --flux-calibration archive selects archived-reference replay; it is a different calibration policy. Missing same-night responses do not silently fall back to archives.

  5. Read the report and identify failures.
    # macOS: open the saved nightly log
open runs/2024-11-14/efospec/index.html

    On Linux, open that file in your browser. Inspect spectra, 2D images, trace/background diagnostics and calibration checks. Exit code 0 means requested stages completed, 1 partial failure and 2 an input/operational error. Run the report stage after a partial reduction so the failures are visible.

  6. Review or change the extraction in the desktop application.
    efospec gui runs/2024-11-14/efospec

    Select the exposure and inspect the spectrum, 2D image and spatial profiles. Confirm the intended source using the acquisition/finder evidence. Use Inspect / Pan / Zoom for navigation; edit the source selector and centre/FWHM/radius controls for geometry. Positions are zero-based raw detector pixels after binning; radius is the boxcar half-width.

    For manual background selection, turn off automatic selection and drag bands on the spatial profile. Review both sides, exclude contaminating traces and save the polynomial degree. The normal bounded policy prefers 30 pixels per side, allows narrowing to 15 and widths up to 50; do not copy another exposure's bands.

    Click Save recipe, then Extract new revision. Expand Revisions & activity, open the completed revision and inspect its diagnostics. Invalid controls disable extraction. Failed-exposure Source review may produce count-level boxcar experiments; do not treat those as flux-calibrated science spectra.

  7. Use a reviewed extraction in a new nightly revision, when needed.

    A GUI extraction does not automatically replace the nightly result. Prepare the exposure-bound reviewed-sources JSON using src/efospec/reviewed_sources.py and docs/epoch-workflow.md: exact raw basename/hash and OBJECT, parent run and recipe paths, recipe hash, and operator identity/background evidence. Then run:

    efospec night 2024-11-14 --reviewed-sources /absolute/path/reviewed-sources.json

    This re-extracts using validated native geometry and creates a new workflow revision. Old archive-grid geometry cannot simply be promoted into the native route. Review the new result before accepting it.

  8. Refresh a saved report or add an IRAF comparison.
    # Refresh the selected result without re-extracting
python -m efospec.epoch_report 2024-11-14
# Optional read-only comparison with matched legacy spectra
efospec night 2024-11-14 --stage report --iraf-comparison

    The comparison looks recursively under the date's data directory for header-identified IRAF flux spectra and matches exposures using provenance and metadata. It does not normalize, shift or replace either spectrum. Inspect ambiguous or missing matches in the report.

  9. Locate the saved products and finish the review.

    runs/DATE/efospec/nightly/current.json selects the workflow revision. Use its saved product/QA paths. Retain native spec1d/spec2d files, recipes, calibrations and earlier revisions. The delivered _f.fits contains primary flux, alternate extraction, sky and statistical uncertainty with validity masks; read BANDID/EXTRPRI to identify the chosen extraction.

    Native PypeIt wavelengths are vacuum; the legacy-compatible flux product is air/topocentric. Do not convert it twice. Review wavelength validation, response support and actual correction history. Experimental/provisional flags and limitations in absolute flux, slit losses, telluric correction or response uncertainty remain meaningful even when the report is complete.

Commands checked against the local CLI and scripts. Workflow references: docs/epoch-workflow.md, docs/desktop.md, src/efospec/nightly.py. The example plots illustrate inspection steps; their apertures and calibration choices are not reusable defaults.

Clean restart after a corrupt PypeIt reduction

From the EFOSpec project directory, stop pipeline jobs and close desktop reduction workers. Preview the date first; add --apply to archive its outputs:

# Show which PypeIt outputs would be moved, without changing any files.
python scripts/cleanup_epoch.py 2024-11-14
# Move all PypeIt outputs for this date into a recovery folder, preserving raw data and IRAF reductions.
python scripts/cleanup_epoch.py 2024-11-14 --apply
# Start a fresh reduction for this date using the original raw data.
python scripts/reduce_epoch.py 2024-11-14
  • Equivalent: efospec cleanup-night 2024-11-14, then repeat with --apply.
  • Moves all runs/DATE/efospec/ outputs—including calibrations, QC, reports and delivery copies—to the printed runs/DATE/archive/cleanup-TIMESTAMP-ID/efospec/. Raw data, IRAF reductions and other dates stay intact. This does not reclaim disk space.
  • A nightly lock blocks cleanup. For a crashed job, --clear-stale-lock works only if its recorded process no longer exists.
  • To undo: stop workers, archive any replacement run, then move the saved efospec/ folder back to its original path in cleanup.json. Restore before using saved manifests; their absolute paths are unchanged.

4 / Package EFOSpec products for WISeREP

Prepare one explicitly reviewed observing night. Keep public classification spectra and private follow-up spectra in separate packages, as specified in the PESSTO Handbook v1.39 (pp. 35–36). Choose the accepted flux products from the exact reduction revision.

Before sending: calibrated spectra and one consistent identity

The handbook already specifies these naming norms. PESSTO Handbook v1.39, pp. 35–36, asks for reduced _f.fits, the full SN/AT or survey designation, separate public/private tarballs, and notice to the upload team if a corrected TXT is outside the tarball. The pipeline draft recommends PESSTOWISE listspectra -c listcandidates. The missing local check was agreement between the TXT, FITS headers and filenames.

  1. Select calibrated products. Never send raw EFOSC.*.fits, extracted _ex.fits counts or native PypeIt spec1d/spec2d as the science upload. A name ending in _f alone does not prove calibration. Check wavelength in Å and flux in erg s⁻¹ cm⁻² Å⁻¹, the source/aperture, wavelength residuals and response coverage.
  2. Review the identity. Use the current TNS/Marshall designation: SN for a confirmed supernova, AT for an unclassified/non-SN TNS transient where that is its recorded prefix, and the full survey name if it has no TNS name. Never infer the target year from the observing date. An OB typo such as 2026advo versus 2025advo requires checking the target record. A classifier suggestion is not a confirmed name.
  3. Correct all delivery copies together. Keep manifest object equal to original FITS OBJECT and keep the original SHA-256. Set delivery_object to the reviewed name and identity_evidence to the checked record/reference. Keep the reviewer and review flags explicit. For example:
"object": "AT2026afqt",
"delivery_object": "SN2026afqt",
"identity_evidence": "Reviewed TNS record/reference here",
"identity_reviewed": true

This is an example, not a classification assertion. For a year typo, use the same fields with the verified year. PypeIt packaging automatically updates delivery OBJECT and matching target cards, names the FITS/ASCII consistently as tSN…_f.fits/tSN…_f.asci (or tAT/survey), and regenerates the table, checksums and audit records. Original raw data and accepted products are unchanged. Matching calibrated 2D copies are updated too; omit plots during a name correction until their visible labels have been regenerated and reviewed.

Verify the actual tarball: python scripts/package_wiserep.py validate --strict PATH_TO_ARCHIVE.tgz. New CLI builds do this automatically. It rejects mismatched table/header/names, raw/count products, non-Angstrom WCS, invalid uncertainties and implausible pixel-like wavelength ranges. The ASCII is rebuilt from the FITS, not copied from a possibly stale file. Scientific calibration accuracy still requires review. Do not send an externally corrected TXT alongside a stale tarball: rebuild a new delivery revision.

Legacy limitation / TODO: PESSTOWISE interactive name changes can still affect only the table; its coordinate-list correction can edit supplied FITS in place. Work on disposable delivery copies, reconcile header/name/table and review all products before packaging. A common immutable legacy identity adapter remains TODO. The new PypeIt correction is implemented in the CLI; old standalone HTML logs retain their old embedded exporter. Regenerate logs for current checks and use the CLI for name corrections.

Checked 25 November 2026 against the supplied PDFs, code and official TNS naming guidance. WISeREP direct documentation returned HTTP 403; the tar contract remains the supplied, locally validated PESSTOWISE examples, not a newly verified server API.

From the nightly HTML log

  • Open Science delivery below the observing log. Choose Public, Private or Do not export per target; check Object / Host. All eligible setups shown are included. Standards, count-only and failed products are excluded.
  • Enter observer/reducer names and the UTC reduction date. Source and private associated groups default to ePESSTO+; edit if needed. Private selections require a future embargo end.
  • Confirm review, click Prepare public / private tarballs, and download each populated archive. Names/date enter the headers and table; science arrays are preserved and checksums recalculated.
  • Use the CLI for name corrections, plots, calibrated 2D attachments or a saved audit record. The browser adds no attachments automatically.

Controls work offline and never upload. Reloading or clearing removes personal entries and restores group defaults. Private settings do not encrypt files or protect a public log; keep unpublished data local or access-controlled.

Source-group defaults

The handbook identifies ePESSTO+ (p. 1), but specifies neither group-field values nor embargo duration. The spelling matches WISeREP EFOSC2 records; no embargo date is assumed.

From the command line

For EFOSpec products, activate efospec. Legacy IRAF products use PESSTOWISE in pessto.

conda activate efospec
cd /Users/avinash/Work/Reduction/EFOSpec
  1. Create the review manifest.
    python scripts/package_wiserep.py init 2026-11-10 \
  runs/2026-11-10/efospec/nightly/REVISION/reduction/products/SELECTED_f.fits \
  --output runs/2026-11-10/efospec/delivery-review.json

    Add more explicit product paths before --output as needed. Initialization records hashes and leaves visibility unset and review flags false. Source group is prefilled with ePESSTO+; private_defaults.associated_groups supplies ePESSTO+ to private entries without their own group list. Public entries retain an empty group list.

  2. Review each selected spectrum.
    • Complete observer/reducer names, reduction date, reviewer notes, source group and quality.
    • Verify identity, wavelength and flux; authorize only the selected hashed product.
    • Choose public/private. Private entries need explicit or default groups and a future proprietary end time.
    • Leave unknown classification/redshift null. List optional plot/2D attachments with their hashes.
  3. Build the packages.
    python scripts/package_wiserep.py build \
  runs/2026-11-10/efospec/delivery-review.json \
  runs/2026-11-10/efospec/delivery/review-001

    The destination contains separate pessto_YYYYMMDD_HH_MM_Rapid_upload_public.tgz and pessto_YYYYMMDD_HH_MM_Rapid_upload_private.tgz for the populated classes. The timestamp is UTC packaging time. Each flat tarball contains the example-matched metadata header/defaults line, primary-only four-band FITS, tab-separated two-column ASCII and explicitly referenced attachments. Full masked FITS, error sidecars, JSON and checksums remain in the local audit folders. Original products are unchanged.

  4. Inspect and ingest.

    ASCII wavelengths are air Angstrom, topocentric observed frame; flux is erg s⁻¹ cm⁻² Å⁻¹ with coefficient 1. Do not convert wavelengths twice. Run python scripts/package_wiserep.py validate --strict runs/2026-11-10/efospec/delivery/review-001/*.tgz and share the separate tarballs with the intended collaborators for their existing PESSTOWISE ingestion. The format is checked against the four supplied October examples, including the defaults line and filter-in-Grating column convention. Optional calibrated 2D images occupy Related-file2; native PypeIt spec2d is not relabelled as a calibrated 2df product. Archive access settings still need to be applied by the ingest team.

## Automatic spatial-profile spike limits

The shared display helper now handles positive spikes without a target-specific
pixel list. A positive peak must exceed 20 MAD-sigma in both prominence and
running-median deviation, have a full width at half prominence of at most two
spatial pixels, and have a >10-sigma core spanning at most three columns. Both
flanks must be finite; protected extraction apertures and marked candidates are
never excluded. Width is measured on the full profile, so a narrow residual at
the top of a broad, bright source does not qualify. This is a plotting heuristic,
not proof of a false astronomical source or a scientific bad-pixel mask.

For SN2026aebl on 28 October, the repeated peak at plotted x=547 has measured
widths 1.07, 1.17 and 1.08 pixels. It and its narrow wings now automatically stop
setting the y limits in all three wavelength panels. The figure annotates the
exclusions, and the plot JSON records every excluded coordinate and renderer
hash. Original summed-profile arrays, curves and extracted spectra are retained;
no smoothing, interpolation, new extraction or flux change was performed.
Old figures are retained under the v3 rescue's
`archive/spatial-profile-before-auto-spikes/` directory.

Verification: 19 focused numerical and real-rendering tests passed, covering
bright resolved neighbours, protected unresolved sources, missing edge samples,
spike wings and rendering without explicit display exclusions. The implementation
uses SciPy's [half-prominence width definition](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.peak_widths.html).

The observing table now has separate **z (NED)** and **z (spectral)** columns.
NED cone searches retain all galaxy candidates within 30 arcsec of the FITS

photometric flags are retained. Pointing-based proximity is not a host identification.

The independent spectral search rectifies the pre-background 2D electrons onto
vacuum wavelengths, subtracts a spatially common sky estimate, and sums within
20 pixels of the selected trace. It searches −0.003 ≤ z ≤ 1 using [O II], Hγ,
Hβ, [O III], Hα+[N II], and [S II]. Blends count as one group. At least three
consistent groups must pass SNR, improvement, width and unmasked-core checks;
localized spatial emission must agree in at least two groups and at least 75%
of strong spatial groups. NED does not enter this search. Unknown blend ratios
receive conservative centroid-error floors. Formal fit errors exclude wavelength,
background and resampling systematics; thresholds are candidate gates, not
calibrated false-positive probabilities. Absorption-only spectra are not covered.

Air-to-vacuum conversion precedes fitting; Astropy applies the multiplicative
heliocentric correction at mid-exposure using the recorded observatory position.

## Why the lamp and standard did not settle the wavelength check

The lamp provides the initial pixel-to-wavelength ruler. Sky lines in the actual
science exposure check whether that ruler moved when the telescope/instrument
changed position. The standard supplies the brightness response; it does not
independently measure that science exposure's movement.

For AT2026agzp the two anchor lines suggest a correction near −5.02 Å. After that
candidate correction, the separate 6363 Å check still misses by −4.24 Å, beyond
the existing 3 Å limit. That is an inconsistent check, not a missing lamp or
standard. The exact cause of this line's disagreement is not yet established.

| Target | Reproduced strict wavelength failure |
| --- | --- |
| AT2026agzp / Gr11 | Held-out 6363 Å residual −4.24 Å; limit 3 Å |
| SN2026abgb / Gr13 | 6363 Å centroid uncertainty 3.33 Å; limit 1.5 Å |
| AT2026agvs / Gr13 | Anchor shifts disagree by 3.19 Å; limit 3 Å |
| SN2026aebl / Gr13 | 6363 Å centroid uncertainty 2.57 Å; limit 1.5 Å |

`scripts/diagnose_rescue_wavelengths.py` reprocesses the raw exposures using
hash-verified native masters, reproduces these failures, compares separate sky
wavelength intervals with PypeIt's resolution-matched sky template, and checks
isolated fitted lamp lines near the source position and on either side.
Results are saved under `QC/rescue-wavelengths-20261109-v2/`.

Those extra comparisons do not yet validate a correction. For example,
AT2026agzp's template estimates are approximately −4.80 Å over 5300–6500 Å,
+1.28 Å over 6500–6800 Å and −5.19 Å over 6800–7400 Å. Some intervals contain
little useful line information; template mismatch, blends and sampling can bias
them. They are diagnostics, without a calibrated uncertainty or an acceptance
claim. The lamp checks reuse fitted line identifications and cannot independently
certify flexure in a later science exposure. No wavelength-dependent polynomial
was fitted to force agreement.

The earlier spatial-profile gaps were a separate plotting problem: one masked
pixel could make a whole summed column undefined. The profile now uses the same
valid spectral rows for every supported spatial column, preserving equal
coverage. Unsupported columns remain gaps; no science pixels are interpolated
to make the plot look continuous.

## Delivered behavior and limits

The new `efospec rescue-daily` route accepts only recorded wavelength failures
with successful native count extractions and supported two-sided backgrounds.
It verifies raw/setup/recipe-product associations and hashes, applies a same-night
exact-setup response, and writes a new revision. All four selected responses in
this run come from matching **VMa2 observations on the same observing night**.
There is no archived-2014 sensitivity fallback.

- Counts and native wavelengths are preserved exactly. Uniform-grid exports
  retain the unshifted arc calibration, air wavelengths and topocentric frame.
- FITS carry `EPSTATUS=PROVISIONAL`, `QUALITY=Provisional`, `WAVEVAL=F`,
  `FLXVALID=F`, `WAVSHIFT=0` and `FLEXURE=UNVALIDATED`. ASCII and plots also warn
  that the wavelengths are provisional. `EXTRPRI` identifies optimal/boxcar
  primary flux; band four is that extraction's statistical uncertainty.
- Flux units are erg s⁻¹ cm⁻² Å⁻¹. Valid numerical flux samples cover about
  96–98% of each delivered grid; this is coverage, not accuracy.
- Wavelength and background-model systematics, response uncertainty and
  resampling covariance are not in the statistical errors. Slit losses,
  tellurics, second-order contamination and absolute flux remain unvalidated.
- The accepted nightly `run.json`, spectra and `nightly/current.json` remain
  unchanged. A separate hash-bound `rescue/current.json` adds these products to
  the report only while their parent matches the current accepted revision.
  The preceding HTML is retained at
  `archive/reports/20261109-before-rescue.html`.

## What is still needed for wavelength acceptance

SN2026abgb's 6363.78 Å failure was audited using the exact saved sky samples in
`QC/SN2026abgb-centroid-audit-20261109/`. The SNR-like ratio 31.8 passes the
threshold of 5; the **3.33 Å formal centroid uncertainty** fails the separate
1.5 Å limit. The generic “weak or unconstrained” wording conflated these gates.
The report and future failures now name the failed gate; the numerical limits
and original failure records are unchanged.

- Sampling near this line is 5.654 Å/pixel, so 3.33 Å is 0.59 pixel. The saved
  projected slit width is 35.34 Å. This uncertainty is not intrinsically fatal
  for low-resolution classification, but it is not a validated uncertainty for
  the entire wavelength scale.
- The original fit has nine samples and five free parameters. Its centroid and
  continuum slope have correlation −0.980. The reported “SNR” is fitted amplitude
  divided by residual MAD scatter, not a calibrated detection significance;
  the fitted amplitude's own formal uncertainty exceeds its value.
- The original centroid is 6374.096 ± 3.329 Å on the unshifted arc scale. The
  unapplied mean anchor shift is −6.384 Å, leaving a +3.936 Å residual against
  the independent line, also outside the current ±3 Å residual limit.
- Diagnostic wider windows retain only wavelengths above the midpoint toward
  neighbouring 6300 Å. Half-widths 36, 40 and 48 Å give centroids 6369.124,
  6369.373 and 6369.265 Å, with formal errors 1.452, 1.428 and 1.303 Å. This
  supports inadequate continuum coverage as a cause of the original instability.
  The trials are correlated and are not an independently validated correction.
  No shift or acceptance change was applied.

Reproduce with `scripts/audit_sky_centroid.py --night 2026-10-28 --failure FILE
--profile FILE --output runs/2026-10-28/QC/NEW-AUDIT`; the audit JSON records
input hashes, parameters, covariance correlations, window bounds and figure hashes.
Interpret covariance using the [SciPy fit documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.curve_fit.html).
For context, [PESSTO §3.2.4](https://arxiv.org/html/1411.0299v2#S3.SS2.SSS4)
uses roughly 1 Å precision for its sky-derived wavelength shifts, despite its
much broader spectral resolution. These are different quantities.

1. Inspect additional usable sky features in each exposure, including blends
   and their spatial variation; establish which measurements have enough
   information for a reliable centroid.
2. Test a correction using one set of trustworthy features, then check other
   features that were not used to fit it. Calibrate any template-based acceptance
   criterion with injected shifts/noise and the actual instrumental resolution.
3. Accept a revised wavelength scale only if those checks agree. Otherwise keep
   the current spectra provisional and report the unquantified wavelength
   uncertainty. Target-specific velocities and precise line positions must not
   be treated as validated by this rescue.

## Method references

the relevant [PypeIt 1.14 sky-subtraction guidance](https://pypeit.readthedocs.io/en/1.14.0/skysub.html)
and [extraction guidance](https://pypeit.readthedocs.io/en/1.14.0/extraction.html).

[Kelson (2003), Optimal Techniques in Two-dimensional Spectroscopy](https://arxiv.org/abs/astro-ph/0303507).
The template diagnostic uses PypeIt's flexure implementation; see its
[flexure documentation](https://pypeit.readthedocs.io/en/stable/calibrations/flexure.html).
The response route follows the native project implementation and
[PypeIt 1.14 flux-calibration procedure](https://pypeit.readthedocs.io/en/1.14.0/fluxing.html).
These references support the method; they do not validate these particular data.

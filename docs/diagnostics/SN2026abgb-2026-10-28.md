# SN2026abgb: background geometry diagnosis

Investigated 2026-11-11. The original failure is a band-placement failure, not
PypeIt solver non-convergence. The current code completes a trial extraction but
loses a genuine neighbouring trace from its background guards. That trial is
**not accepted** and does not replace the selected nightly reduction.

## What happens

1. Raw-image finding detects the central source near **102.58** and a broader
   neighbour near **160.45**, with FWHM **18.49**. The preliminary sky model is
   fitted successfully: exit status zero and reduced χ² about **1.04**.
2. Source finding after that fit is restricted to its interpolation interval,
   roughly pixels **56–149** at the median row. The broader neighbour's centre
   falls outside it. Finding produces a candidate near **142** on the rising
   side of the broader source instead of retaining the original trace.
3. The original code guards that edge candidate. Every offered final-band width
   fails placement; width 15 fails in **860/942 rows**. The final selector calls
   the fitting solver **zero times**, then reports “No bounded two-sided
   background converged.” Increasing its iteration limit cannot fix this stage.
4. Current trace validation rejects the edge candidate because neither flank can
   be tested within the restricted interval. The real neighbour is also absent
   from the retained guard list. Current extraction completes with **20 pixels
   per side**, degree **2**, and measured aperture radius **23.5**.
5. An independent local-contrast check on the full calibrated window, using the
   original detected trace, supports the broad neighbour in **all six spectral
   bins** (signed contrast/error approximately 148–301). The candidate near 142
   has negative local contrast in every bin. This confirms the lost-neighbour
   problem without assigning an astrophysical identity to either source.
6. Applying the existing 1.5-FWHM guard to that original neighbour gives a radius
   of **27.74 pixels**. The current trial's background input mask enters this
   guard in **all 942 rows**, with a median **14 selected pixels per row** inside
   it. Numerical completion therefore does not establish clean background bands.

There is a second validation issue: the reported held-out ring at radii **13–16**
lies inside the **23.5-pixel** measured source aperture. Its mean residual,
**+0.773** per-pixel noise units, cannot independently validate the background.
The selector already marks its geometry unresolved. The independent 6363 Å
wavelength check passes (−0.858 Å); that does not validate background subtraction.

## Changes to develop and validate separately

- Preserve possible contaminants across detection stages. Test their local
  contrast using supported calibrated pixels; never equate an untestable flank
  with an absent source. Keep accepted neighbours' guards even when a later
  search window omits their centres.
- Distinguish unavailable geometry from an attempted fit that did not converge.
  Record source/guard bounds, which side failed and whether the solver was called.
- Require a scoring ring outside the measured aperture and all neighbouring
  guards. If none exists, keep the uncertainty explicit.
- Only then test wider calibrated windows or reviewed finite bands in new
  revisions. Require two-sided support, positive-source checks, final-trace
  checks and wavelength validation before proposing adoption. A wider window
  must also be inspected for additional sources.

Regression cases should include a real broad neighbour outside the bootstrap
search interval, its truncated edge candidate, and a scoring ring inside a
measured aperture.

## Shared-engine follow-up, 12 November 2026

The nightly integration now retains initial neighbours supported by local
contrast, preserves guards when their flanks are untestable, keeps fractional
aperture radii during refitting, and scores only background pixels outside the
aperture and neighbour guards. Synthetic broad-neighbour and holdout regressions
pass. Geometry failures explicitly state when the sky solver was never called.

The new `QC/nightly-integration-20261112/` revision retried this exposure with
calibrated spatial half-windows 100, 150 and 200. Every attempt still fails band
placement under the retained neighbour exclusions and gap limit. The change
therefore prevents the contaminated apparent success described above; it does
**not** establish a usable new SN2026abgb spectrum. Review of the guarded band
geometry is still needed before any adoption. Original products and the selected
nightly reduction remain unchanged.
